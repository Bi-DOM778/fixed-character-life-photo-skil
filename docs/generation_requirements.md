# Generation Requirements — 生成前硬性要求

本规则约束生成前的决策和实际发送的提示词，不以提示词字数保证效果。短指令可以调用已完整定义的方案；不能把用户一句“生成一些生活照”直接等同于授权自行确定全部画面。

## 1. Intent Gate

生成前必须得到以下内容，可来自当前指令、同一对话已确认方案或用户明确授权采用的预设：

| 必须明确 | 内容 |
|---|---|
| 身份 | 哪个角色、哪张批准图、不可改的面部特征；可访问且无冲突 |
| 场景与日常行为 | 在哪里、正在做什么；不能只写“生活化”“好看” |
| 表情与视线 | 微笑/大笑/平静等、看镜头或看向何处；不能默认复制身份图表情 |
| 画面 | 景别、机位高度、人物角度、自拍或他拍；画幅可沿用已确认偏好 |
| 外观与质感 | 服装、发型是否保留或改变；光线方向和软硬；保留哪张图的质感 |
| 数量与变化 | 张数；多张是否同一系列，以及主要变化维度 |

每项标 explicit、confirmed-context、delegated、proposed 或 missing。前四者中 proposed 仍未确认：关键项若只有 proposed/missing，先给具体方案并集中询问，保持生成待定。不要以“我先做三张”代替用户授权。用户明确说“自行挑选/按预设/其余自动补全”时，授权范围内可直接补全并记录 delegated；不反复要求确认。无关紧要的杯子材质或背景小物可自行补全，不要求逐项审批。

简短请求示例：“用所选角色生成生活照” → 先提一个具体场景，询问用户想要的动作、表情及拍摄感觉；已有脸参考、4K 偏好无需再问。“按刚确认的咖啡馆方案生成” → 若方案完整，直接执行。

## 2. Prompt Gate

发送工具前必须编译 [Shot Brief](../templates/shot_brief.md)，内部或保存文件即可，不强制把长表格展示给用户。

- BASE：实际 primary 图及各输入职责。只锁当前图能支持的身份，不借用场景人物的脸或体型。
- KEEP：脸型、眼形眼距、鼻唇比例、年龄印象、稳定特征和已确认质感。未知的体型比例保持 unknown。
- CHANGE：场景、服装、发型、表情、视线、动作、机位及场景光线的明确差量；将 Hair/Pose/Composition/Environment/Light 五类锚点落到可见行为。
- AVOID：本次风险对应的少量负面约束，直接作用于实际工具提示，而非仅写在报告里。
- SUCCESS：能从结果图检查的标准；身份、场景还原、融合、质感和实际像素分别验收。

Delta-only 是省去重复身份描写，不是省掉目标画面。不得只把“生活照、4K、真实感”发给工具；也不机械堆叠修饰词。设备名必须转成透视、景深、曝光、噪点等可观察行为。

## 3. Identity 与 Shot Variables 分离

面部身份不等于固定表情、发型或姿势。例如，把“高马尾、正脸、同一微笑”无条件写入 KEEP，会令变化局限于背景和衣服；只有本次用户明确要求保留这些状态时才应锁定，不能把示例造型当作角色身份。

- 发型状态、表情肌肉、视线、头身姿态属于 Shot Variables，除非用户明确要求保留。
- 发际线、基准发色和稳定面部结构可为身份 Anchor，视角色定义而定。
- 没有侧面/表情参考不等于永远正脸微笑；按 Selector 记录覆盖不足，必要时先做 Stage A，身份通过才进入 B。
- 多图方案逐张定义动作/表情/构图，不默认为换背景套同一头像。用户要求同表情或同机位的系列应尊重该要求。

## 4. 质感提示取舍

保留用户提出的优点：真实纹理、适度肤色层次、参考已有的微妙不对称和可信摄影光影。默认 realism: preserve，仅有具体缺陷时 targeted。

| 观察到的问题 | 可选最小修正 | 不默认添加 |
|---|---|---|
| 蜡感/涂抹感 | 恢复符合景别的细微肤理、唇纹和自然光泽，避免过度磨皮 | 大毛孔、皱纹、痘痘、随机瑕疵 |
| 肤色成一块 | 保留自然血色与局部色差，让冷暖和明暗由场景光产生 | 重黑眼圈、红鼻、额外苍白或老化 |
| 模板化对称 | 保留原参考已有的不对称与眉毛、碎发细节 | 新造高低眉、改变左右眼形 |
| 棚拍脸贴在背景上 | 统一光向、曝光、反射、景深、锐度和噪点，检查接触阴影 | 每张都用 85mm、f/1.4、强颗粒或极浅景深 |

CFG、重绘强度等参数仅在当前工具明确支持时使用；数值由具体工具、参考和本次目标决定，不预设跨模型通用区间，也不得假称已经设置。负面词也不机械排除所有柔光：要避免抹除细节的柔焦，保留参考中成功的柔润光线。

## 5. 经验与验收边界

返修以当前用户认可的成功底图为比较基准，保留已成功的身份、构图、光泽和受光，仅改变本次明确的变量。失败修正版不能取代原身份基准；新场景仍需独立检查人物与环境是否统一。

本公开包没有附带用户照片、批准图库、私人生成记录或预置的视觉测试结果。示例只是提示词与验收方式的演示。静态规范通过、模型生成完成、视觉 QA 和用户采纳须分别记录；未运行项保持 NOT-RUN。
