# 4K Photo Delivery

本 Skill 的照片默认必须按 4K 交付。这里采用可执行的照片约定：长边 3840 像素，保持用户指定画幅，不强制裁成视频的 16:9。用户给定更高分辨率或明确覆盖本要求时遵循其最新要求。

| 画幅 | 目标像素 |
|---|---|
| 3:4 竖版 | 2880 × 3840 |
| 4:3 横版 | 3840 × 2880 |
| 2:3 竖版 | 2560 × 3840 |
| 3:2 横版 | 3840 × 2560 |
| 9:16 竖版 | 2160 × 3840 |
| 16:9 横版 | 3840 × 2160 |
| 1:1 | 3840 × 3840 |

其他画幅以长边 3840 计算短边；记录四舍五入或工具对齐造成的实际差异。尺寸约定不代表新增纹理、可打印尺寸或原生细节保证。

## 执行顺序

1. 生成前根据画幅填写 requested_dimensions。工具暴露尺寸设置且支持目标时直接设置；只有提示文本时可请求目标，但输出仍需核验。检查工具的像素总量与长边限制，不编造不存在的参数。
2. 从真实输出文件或可靠工具元数据读取宽高，填写 actual_dimensions。预览图尺寸不能替代交付文件尺寸。
3. 不足目标且有可用高质量放大能力时，保持画幅、身份、表情、光泽与纹理进行放大；检查脸部及头发是否出现假细节和锐化光晕。标记 provenance: upscaled，并记录原始尺寸。不要把放大称为原生 4K。
4. 无可用放大工具、目标超过能力或放大损害质量时，保留最佳原图，标记 resolution_status: UNMET，说明实际尺寸与限制；不宣称已满足要求，也不默默改裁切。
5. 仅输出提示词时记录 4K 目标，像素核验为 NOT-RUN。A 阶段内部草图可低分辨率，最终照片交付必须执行此门。

只写“4K / ultra HD”不构成像素设置或验收。一般尺寸插值可改变文件宽高，却不证明获得新的真实细节。仅在获得可用工具和权限的情况下执行放大，不自动安装服务或切换收费 API。

## 交付字段

```yaml
resolution_requirement: 4k-long-edge
requested_dimensions: [2880, 3840]
actual_dimensions: null
source_dimensions: null
provenance: unknown # native | upscaled | unknown
resolution_status: NOT-RUN # PASS | UNMET | NOT-RUN
texture_after_upscale: NOT-RUN
```

PASS 表示文件达到目标像素且画幅保持；身份、场景和质感仍需各自 QA。历史文件不会因本规则自动变为 4K。
